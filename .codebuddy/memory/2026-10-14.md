**同一个坑在购药里踩了两次（第二次：`折叠开`）**：上次只堵了"主城常驻"，但规则表第 44 行 `{名:"折叠开"}` 排在 `主城` 之后——地图列表里**折叠项永远存在且不止一个**，主城展开退役后每轮改命中 `折叠开` → 照样永不滑动。修法：扫表循环里加 `if r.名 == "折叠开" && 主城已展开 { continue }`（折叠开只在"找主城"阶段有用，主城一展开即退役）。
**教训（通用）**：写平铺规则表时，要逐条问"这条规则的目标物在屏幕上是不是恒常存在"——恒常存在的（常驻文字、列表折叠图标、面板标题、标签页）**全都必须有阶段退役条件**，否则兜底滑动/翻页永远执行不到。退役方式两种：`一次:true`（点一次就退）或阶段标志（如 `主城已展开`）。

### ✅ 十九次：编译报错「initialization cycle for 任务表」（同日，真机 `go build` 暴露）

报错链：`任务表(var) → 买药跑 → 买药场景 → 切下一个任务 → 任务表`。

**根因**：`var 任务表 = []任务{{"买药", 买药跑, ...}}` 是**包级变量初始化式里引用函数**，而该函数（经 `切下一个任务`）又引用回这个变量 → Go 判定初始化循环，编译失败。
**修法**：`任务表` 改成 `var 任务表 []任务`（只声明）+ 新增 `init()` 里赋值。函数**体内**引用变量不算初始化依赖，循环断开。

**⚠️ 通用坑（zt 以后加任务/加表必看）**：凡是"表里放函数指针、而这些函数又会回头查这张表"的写法（任务表 / 步骤表 / 规则表 + 调度函数互相引用），**表必须在 `init()` 里填，不能写 `var X = []T{...}`**。触发条件是"函数指针表 + 环回查询"，这两个一碰上就必然报 initialization cycle。
