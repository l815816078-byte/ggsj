# ggsj 项目长期记忆（play 自动化脚本，Go）

## 一、硬约束（用户多次纠正，最高优先级）
1. **🔴 未经允许不准加新东西**（新变量/常量/函数/字段/判断/配置/日志…）。让修就只修，让改一处就只改一处。"项目规则 > 我的判断"。落笔前先读 CLAUDE.md 对应小节逐条对照。
2. **一次性/单处使用的坐标、常量、颜色、阈值一律内联数字**，禁抽 `var/const`（≥2 处复用才抽，抽了必须处处复用）。
3. **不新增 md 里没有的方法/封装**："识别到就点它"统一 `查找点击延时`，不要自造 `ClickRecog` 那类（老引擎 plugin/wait.go 已废弃）。
4. **循环手写 `deadline := time.Now().Add(...)` + `for ...Before(deadline)` + `if 已停止()`**，不编"最大轮数"常量（除非用户说）。
5. **不动用户的嵌套循环结构**（`for A { for B {} }` 层级/顺序/归属保持原样）。
6. **只改用户点名的那一项**，不顺带改旁边字段；改预设就只加那一项，已有字段（相似度/偏移/中坐标）原样保留。
7. **识别日志里的 `sim:1.000` 不算用户指定阈值**：只有用户明确要求配阈值时才套 CLAUDE.md 的"1/1.000 → 0.95"。
8. **🔴 配置一律集中到 `mian/点库.go`**（`特征表`/`区域表`/`偏移表`/`滑动表`/`业务配置`）。判据：任何"可调参数/坐标组/阈值/名单/物品表"都进点库；**任务 .go 只留流程逻辑**。滑动坐标也必须在 `滑动表`，不许内联。
9. **新增/移动包级变量前先 search_content 搜重名**（曾重复声明 `落花商店已做完` 报编译错）。改造状态变量三步：搜旧名引用 → 区分「跨轮状态」（留包级，如 落花商店已做完/成长第几类/子任务表指针）与「循环内临时进度」（必须局部，如 滑了/加过/点到）→ 删旧 var 时连带删重置函数里的赋值。
10. **🔴 中文标识符不导出 → 所有 .go 必须在同一目录同一包**，不能分子目录（汉字非大写字母，跨包访问全红）。曾移进 `mian/process/` 全报错，已全部搬回 `mian/` + `package mian`。
11. 工具坑：PowerShell 内联 `$变量` 会被吃 → 批量改文件写成 `.ps1` 再 `-File` 执行；`go run` 本机被权限拦。

## 四、ClickAdaptive（从 plugin/wait.go 原样移植到 `mian/基础.go`）
```go
func ClickAdaptive(scanTimes, gapMs int, isDone func(name string), btns ...Btn) bool
```
- 扫 `scanTimes` 遍（**不按超时**），遍间 `RandomSleep(gapMs,gapMs)`（`gapMs<=0` 不歇）。6 个调用点统一 `ClickAdaptive(3,500,...)`：背包格子、领取邮件红点、画册内层、支线⑤接取链、加护①②③、加护召唤阶段。
- 辅助：`Btn`、`btn(name,opts...)`、`btnStop(name,...)`、`skipTolerance=3`、`absInt`、`regionText()`（日志用区域文本）。
- 语义：`Stop` 命中即停返回 true（不点击）；`Done` 命中只标记；`SkipStreak` 连续同位置命中拉黑；`SkipIfRecog` 命中他则跳过本按钮；`ClickOffset` 点击偏移。
- **使用判据**：老脚本用 ClickAdaptive 就照抄用，**不要自己判断该不该**（曾自作聪明回退成 `查找点击延时`，用户说"还是加回来吧"）。`扫弹窗(名单[,轮数])` 用于"扫一遍看有什么挡路的"。

## 六、🔴 同质列表一律「一次点完」，不要每轮一个
- 红点/装备/类型表/战力点 → `for _, 点 := range 识别多个(...) { 点它; 处理它带出的东西 }` 一次全点完，不用 `第几个` 每轮推进。
- 用户原话："不要这样 直接点完啊 还出去干屁啊""所有这种 分了 都改哈。所有代码"。已改：领取邮件、福利、画册、门派战斗、每日任务、成长。
- ★ `识别()` 返回 3 值，必须 `if _, _, x := 识别("X"); x {`，不能 `if 识别("X")`。
- **例外（探测型，每轮一个）**：背包格子（连续空格探测）、落花商店（找+滑+加1+读数）、气运类型表（连续点不到才切）、福利翻页、点位寻路。**判据**：元素本身是重活（进场挂机几十分钟）或下一步依赖当前屏幕探测结果 → 每轮一个；纯同质点击 → 一次点完。
- **不可中断性是已知代价**（用户知情）：for 期间主循环的 `已停止()`/超时/卡死检测/扫弹窗/HUD 失效，只在元素入口查 `已停止()`。别拿这个理由改回分轮。

## 七、🔴🔴 不要给用户描述的流程"加戏"
用户给的流程长什么样就写什么样，一个字不加。被骂"复杂/傻逼"时往**删**的方向改，不是换语法糖（if→switch 换皮会被识破）。
- 用户说"主菜单，成就，成就列表，做事，退出" → 就写这 5 步，不插"在不在主界面"判据、不加 default 兜底。
- 用户贴日志 = 加预设，**不要顺带改调用方逻辑结构**。
- **"先点再认"优于"先认再决定点不点"**：`查找点击延时("邮件")` → `if _, _, ok := 识别("邮件列表"); ok { 干活 }`。
- 我犯过的加戏清单（自查）：三层嵌套 if/else、switch 三段链、`在面板`/`在主界面` 自造变量、用【退出】当卡面板判据、给主任务编"优先级链 vs 状态分流"理由。
- **🔴🔴 滑动是业务动作，绝对不准删/不准改**（用户暴怒："滑动不能动啊"）。"一次跑完"= 去掉分轮状态变量，**不等于**删滑动（曾误删画册滑动）。`滑动表` 键名、`RandomSwipe` 参数顺序、`cx := (a+b)/2`、滑动次数上限一律原样。现有滑动：画册列表、福利天数、福利积分、每日列表、开面板(落花+每日)、落花商店、成长列表、门派面板、找地点、找主城、扫弹窗"省电模式"。

## 八、子任务「状态 + 完成判据 + 退出」规范
三条铁律：①【退出】永远都在，**绝不能拿它当完成判据**；② 完成判据 = "该处理的没了"（进度走到尽头），退出只是收尾；③ **没东西处理也要正常退出、也算完成**。
- 迭代型：`第几个 >= len(列表)`（=0 也成立 → 直接退）；面板型（背包）：分类走完 **且** `识别("背包")` 不在；次数型：`次数 >= 上限`。
- 不要加"空几轮 / 连续 N 轮确认"；退出只留一处不重复兜底；不写"没点到某按钮就不退出"的拦截。
- 进度状态（`xxx第几个`）必须跨轮保留，超时/打断回来接着干（重置只在完成后调，超时不清）。
- 我犯过的错：拿 `查找点击延时("退出")` 返回值当完成 / 拿 `识别("退出")` 判"不在"当完成 / 加空几轮计数 / 加护命中召唤用光就 return 不点退出（用户："召唤用光了要退出的啊"）。

## 十、架构事实
- **新框架 = `mian/`**（原 `zt/`，已改名），23 个 .go 同包 `package mian`。旧 `plugin/`、`assets/tasks/`、`assets/recogs.json`、`bot/`、`task/` 全废弃（仅考古）。`zt/` 残留副本勿改。
- **主循环（`主流程.go`）**：每轮 `跑当前任务()` 调 `任务表` 当前任务的 `跑()`（环，指针前移 = 轮转）。卡死：`适配次数 >= 20`（连续无命中）→ 切下一个任务。超时：`任务最大执行秒[当前任务]` → 切下一个任务。轮间 `RandomSleep(1000,1500)`。
- **挂机（`挂机.go`）**：`挂机跑()` 被 野外挂机/每日任务/落花战场/门派战斗 调用 = "谁调它谁就是挂机"；`跑子任务()` 在挂机期间跑 9 个子任务（各带冷却）。两条独立判据：**有动静**（怪物命中/省电_金币变化，100 秒无动静 → 重跑）；**场景**（仅落花：100 秒不见 `场景_落花战场` → 重跑）。
- **挂机参数表（点库 `init()` 里赋值，防初始化循环）**：`type 挂机参数 struct { 判据 func() bool; 场景 string; 跑子任务 bool; 时长秒 int }` + `挂机参数表 map[string]挂机参数`。`挂机.go` 里零 `当前任务 == "xxx"` 硬编码；加新挂机任务只改点库。教训：布尔组合判据不能用 `判据/次判据/第三判据` 三个字符串字段（"太傻逼了"）→ 用 `func() bool` 闭包；判据逻辑放点库，不要在 `挂机.go` 留函数。
- **基础原语**：`识别()`（单）/ `识别多个()`（多，需 `寻找个数>1`）/ `查找点击延时()` / `扫弹窗()` / `持续找色()` / `是否存在()`。
- **HUD**：状态行 = `当前任务 + 当前状态`（`core.SetStatusColor`），进度行 = `(已运行/上限)`（`core.SetTaskProgress`）。
