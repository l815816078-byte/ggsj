## 🔴🔴 子任务「状态 + 完成判据 + 退出逻辑」规范（2026-10-15 用户原话定，以后新增子任务一律照此）

### 三条铁律
1. **【退出】按钮永远都在**（面板固定按钮，点完也不消失）→ **绝不能拿"退出在不在 / 点到没点到"当完成判据**。
2. **完成判据 = "该处理的没了"（进度状态走到尽头）**，退出只是收尾动作。
3. **有没有东西处理，都要正常退出、都算完成**（用户："红点可能是没有的，没有也要退出，也算完成"）。

### 具体写法
- **进度状态必须有**（`xxx第几个` 之类）：跨轮推进，超时/被打断回来**接着干**（重置只在完成后调，超时不清）。
- **完成判据**用"状态走到尽头"：
  - 迭代型（红点/类型表）：`xxx第几个 >= len(列表)` —— **=0 也成立 → 直接退**（本来就没东西）
  - 面板型（背包）：`分类走完` **且** `识别("面板名")` 不在（面板真关了）✅ 这个可以用
  - 次数型（福利翻页/下拉）：`次数 >= 上限` → 退出
- **不要加"空几轮 / 连续 N 轮确认"**（用户明确："不要什么空几轮啊"）—— 没红点就直接退。
- **退出只留一处**（次数上限那个），**不重复兜底**（福利"翻页/下拉都没了→退出"被删，用户："用翻页的就能控制退出"）。
- **不要加"没点到某按钮就不退出"的拦截**（灵力修炼的 `if !已点红 { return }`、领取成就的 `if !已点绿 { return }` 都被删）—— 没点到也要正常退出。

### 我犯过的错（绝对别再犯）
- ✅→❌ 拿 `查找点击延时("退出")` 的返回值当完成（退出永远在 → 第一轮就完成，活没干）
- ✅→❌ 拿 `识别("退出")` 判"不在"当完成（永远不成立 → 永远完不成）
- ✅→❌ 加"空几轮"计数（用户明确不要）
- ✅→❌ 把背包 `识别("背包")` 判面板关改成无条件完成（用户明确那个是对的）
- ✅→❌ 加"没点到红点/绿色按钮就不退出"的拦截
- ✅→❌ 加护命中召唤用光就直接 return 不点退出（用户："召唤用光了要退出的啊"）

## 架构事实（排查过、已确认）
- 「挂机中」插件的 `跑子任务()` 会在 野外挂机/每日任务 执行期间**同步嵌套**跑 9 个子任务（plugin/挂机中.go:63-95），走 `plugin.RunTask → Scheduler.RunTaskNow → executeTask` 新建引擎。日志里看到"任务 A 执行中冒出任务 B"通常是这个，不是调度器并发。
- `Scheduler.RunTaskNow` 只校验目标任务自身是否 Running，**没有全局单飞锁**。
- `Scheduler.executeTask` 的超时分支只置状态就 return，不终止 `engine.Execute` 的 goroutine → 存在野协程继续点击。
