## btn 连点功能（用户："btn方法加个连点功能 可允许我连点多少次 每次间隔多少秒"）
- `Btn` 加两字段：`ClickTimes int`（连点几下，<=0 视 1）、`ClickGapMs int`（间隔**毫秒**，0=不歇）。单位跟项目一致用毫秒（不是秒），1000=1 秒。
- 新构造 `btnMulti(name string, times int, gapMs int, opts ...any)`（照 `btnNeedHit`/`btnStop` 的对称写法，避免和 `btn()` 里 int 的"区域/SkipStreak/ClickOffset"解析冲突）。例：`btnMulti("加号", 10, 500)`、`btnMulti("加号", 5, 1000, 700,400,760,460)`。
- 实现：点击处改 for 循环，第 2 下起才 `RandomSleep(gapMs,gapMs)`；每下前查 `已停止()`；日志 `[自适应]点击【名】(x,y) 第n/N下`。**连点在同一坐标**（不重新识别）。
- `hitNames[名]` 整轮连点只记一次（不影响 NeedHit 前置语义）。
- **间隔改成范围随机**（用户："间隔要范围的 范围内随机"）：`ClickGapMs` 由 `int` 改为 `[2]int{最小毫秒, 最大毫秒}`，每次在范围内随机；只给一个数 = 固定值；两数都 0 = 不歇。
- 用户纠正"间隔要透传 到 最后点击的按钮里" → 不再用单独的 `RandomSleep` 做间隔，而是把 `ClickGapMs` 作为 **delay 参数直接透传进 `RandomClickInAreaWithDelay(x1,y1,x2,y2, d[0], d[1])`**（core 该函数本就支持 1~2 个 delay 毫秒参数，0,0 = 不额外延迟）。只有 `ClickTimes > 1` 才透传，普通单点走默认延时（1500~2000）。
- `btnMulti` 签名 `btnMulti(name string, times, gapMin int, gapMax ...int)`：gapMax 可选（不传=固定 gapMin）。**区域走点库预设、不内联**（加号坐标已在点库配好）；早先想加 opts 透传有错位 bug，已去掉。
